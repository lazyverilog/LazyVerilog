# v2.2.0 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a crash/hang fuzzer and correctness-invariant harness covering every LSP request type, plus `documentHighlight` and `selectionRange`, with nightly and per-commit CI.

**Architecture:** Two harnesses. (1) `tools/lsp_fuzz.py` drives the real `lazyverilog-lsp` binary over stdio (the transport, threading and incremental-sync paths are only reachable there), with a crash/hang/sanitizer oracle and an incremental-vs-reopen oracle; sessions are recorded as JSONL and replayable. (2) `tests/test_invariants.cpp` runs in-process Catch2 property checks (rename/references, definition back-link, formatter, folding) over a corpus directory. The fuzzer derives its request mix from the server's advertised capabilities, so any new provider without a generator fails the fuzzer instead of going untested.

**Tech Stack:** C++20, slang, LspCpp (`build/_deps/lspcpp-src`), Catch2, CMake/CTest, Python 3 (stdlib only), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-24-roadmap-design.md` (section "v2.2.0 — Hardening"; committed as `38fd05b` on `fix/formatter-round-v` — cherry-pick it onto the work branch).

## Global Constraints

- Work on a new branch `feat/v2.2-hardening` from `main` (worktree via superpowers:using-git-worktrees); `fix/formatter-round-v` has unrelated uncommitted formatter work.
- Fuzz exit gate: ≥ 1 h seeded run on `rtl1k` under ASan/UBSan, 0 crashes, 0 sanitizer reports, 0 unanswered requests; watchdog fails any reply slower than **10 s**.
- Per-commit CI smoke slice: **60 s**. Nightly fuzz job: Linux only.
- Invariants run over every file in `tests/rtl` (nightly); each violation gets a fix commit or a tracked exclusion.
- `selectionRange`: live tree or token scan; **no new index fields**; no full-AST walk on the request path.
- New features are in the fuzzer's request mix from day one.
- Windows CI has no POSIX libc: guard POSIX-only calls with `#ifdef _WIN32`, tests included.
- New `src/features/*.cpp` files go in **both** `LAZYVERILOG_SOURCES` (CMakeLists.txt ~line 303) and `LAZYVERILOG_TEST_SOURCES` (~line 422).
- Hand-built JSON only via `json_quoted()` / `append_json_string()` (`src/string_utils.hpp`).
- Python tools: stdlib only, run with `python3 -I` in CI.
- Positions are LSP UTF-16 code units; use `lsp_col_to_byte_offset()` (`src/string_utils.hpp:260`) for conversion in C++.

## Review Focus

1. Fuzzer must drain the server's stderr on its own thread; a full stderr pipe deadlocks the server and would read as a "hang". Covered by Task 3 test `test_stderr_flood_is_not_a_hang`.
2. Incremental edits touching non-ASCII text (UTF-16 surrogate pairs): the fuzzer's document model must match the server's. Covered by Task 3 test `test_apply_change_utf16`.
3. `selectionRange` at a position past EOF or in an empty document must still return exactly one entry per requested position. Covered by Task 2 test "selection range: position past end of file".
4. `$/cancelRequest` for an already-answered or never-issued id must produce no response and no crash. Covered by Task 3 generator (cancels pick from all issued ids plus one unknown id) and test `test_session_mix_includes_stale_cancels`.
5. `didChange` / requests for a URI that was never opened (or already closed) must be answered without crashing. Covered by Task 3 generator (1 in 50 requests target a closed URI) and test `test_session_mix_includes_closed_uri`.
